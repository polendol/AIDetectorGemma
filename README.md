# AI Text Detector

## Description
This AI detector stems from a need to ensure no traces of AI-generated text are found in academic texts. Given that 
papers in preparation are privacy-sensitive, this programs ensures that files can be evaluated for AI-generated text 
without submitting them to currently available online programs. It uses perplexity score to calculate if the text was 
AI-generated or not. Gemma model is used to make sure it is able to detect Gemini-generated structures, nowadays widely 
used by academics. This model is run entirely locally through Ollama. 

To optimise the analysis, text is analysed by chunks of 700 characters (100 words), imitating the
average paragraph size of academic texts. Additionally, perplexity score (low/medium/hich) and predictability score 
(1-10) are requested for each chunk to obtain a more precise assessment of the text.Analysis must be done paragraph by paragraph,
as sentence flow is one of the characteristics of Gemini generated text.

Gemma 2 model was not sufficient at recognition of AI-generated text, therefore, the model was updated to Gemma 3 (4B),
(`gemma3:4b`) and the quantization aware trained version fo the model (`gemma3:4b-it-qat`)

The input files must be .txt files. Report is generated as .txt file within the same project. 

## Docker

### Requirements
1. **Docker:** Installed and running (Docker Desktop on Windows/macOS or Docker Engine on Linux).
2. **Docker Compose:** Included by default with Docker Desktop, or available via `docker-compose-plugin`.
3. Hardware: Minimum 8 GB RAM recommended. At least 6 GB of free disk space for Ollama base images and Gemma 3 weights.
4. Network: Internet access on first run/setup to pull models via Ollama.

### How it works
1. **Web interface:** The container runs a Gradio web app on port 7860. You upload a `.txt` file in your browser and download the report from the same page. No folders need to be created or mounted.
2. **Hugging Face model cache:** Model weights are cached in a named Docker volume (`hf_cache`). The ~1.7 GB model is downloaded only once, on the first run, and reused afterwards.
3. **Reports:** Each report is shown on the page and offered as a `.txt` download named after your file (e.g. `my_essay.txt` becomes `my_essay_report.txt`). Reports are not stored on your computer unless you download them.

### Step by step
1. Build and start the application:`docker compose up --build` 
2. Wait until the logs show that Gradio is running. The first start is slow because the model is downloading.
3. Open http://localhost:7860 in your browser.
4. Upload a `.txt` file, wait for the analysis to finish, and click the download link to save the report.

AI_detector_Gemma3 or AI_detector_Gemma3qat for the quantized version


Enter the input file name
Enter the desired name of the .txt report that will be generated 

## Output
Generates a `.txt` report with per-chunk analysis including:
- Perplexity estimate
- Predictability score
- AI signature examples
- Brief reasoning

## How It Works
1. Reads the input `.txt` file
2. Splits the text into chunks of ~700 characters (~250-300 words)
3. Runs each chunk through the gemma3:4b model with the following prompt:
  Analyze this text for AI signatures. 
  Provide the following in your report:
  PERPLEXITY ESTIMATE: (Low/Medium/High)\n"
  PREDICTABILITY SCORE: (1-10, where 10 is highly robotic)
  EXAMPLES: specific examples of all sentences or structures in the text most probably generated by AI."
  ANALYSIS: Brief reasoning.
4. Writes a full report to the output `.txt` file

## Files Structure
- `AI_detector_Gemma3.py` - main program, run this to launch the app (Gemma3:4b)
- `AI_detector_Gemma3qat.py` - variant using the QAT (Quantization-Aware Training) version of Gemma3
- `AI.txt` - file with an example short AI-generated text (for testing)
- `reportXX.txt` - detection reports generated for each XX file
- `requirements.txt` — Python dependencies
- `README.md` — this file

## Notes
- Chunk size is set to **700 characters** for optimal model performance
